# Project Glossary

Ubiquitous language for `brian-ed3d-plugins`. Each term means the same thing in code, docs, and conversation.

## Marketplace and Plugin Structure

- **Marketplace**: the registry of plugins listed in `.claude-plugin/marketplace.json` at the repo root. Plugins are installed individually via `claude plugin install <name>@brian-ed3d-plugins` (`.claude-plugin/marketplace.json`, `18f3b80`).
- **Plugin**: a directory under `plugins/<name>/` shipping any combination of skills, agents, commands, hooks, and scripts. Each plugin has its own manifest at `.claude-plugin/plugin.json`. Hook-only plugins place the manifest under `hooks/.claude-plugin/plugin.json` instead.
- **Skill**: a `SKILL.md` file under `plugins/<name>/skills/<skill-name>/` providing structured instructions to Claude for a specific task. Loaded into the model's context when invoked. A skill is `user-invocable: true` if the user can trigger it via `/<skill-name>`; otherwise it's invoked by other skills or agents.
- **Agent**: a markdown file under `plugins/<name>/agents/<agent-name>.md` with frontmatter declaring `name`, `model`, and `description`. Dispatched via the `Task` tool with `subagent_type: <plugin>:<agent-name>`.
- **Command**: a slash-command markdown file under `plugins/<name>/commands/<name>.md`. The user types `/<name>` to invoke; the command body is loaded directly into the model's context.
- **Hook**: a Python or shell script under `plugins/<name>/hooks/` declared in a `hooks.json` config. Triggered by Claude Code on lifecycle events. Returns a JSON decision on stdout.
- **Hook events** seen in this marketplace: `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `Stop`. Matchers (where used) include `Bash`, `Write|Edit`, and the SessionStart variants `startup|resume|clear|compact`.
- **Auto-discovery dispatcher**: the `denubis-hook-pretooluse-dispatcher` plugin scans enabled marketplace plugins for `hooks/pretooluse-bash.sh` and a `~/.claude/hooks/pretooluse-bash.d/` drop directory, sorts by priority comment, and runs each with the original stdin. Used by `denubis-hook-gh-fork-guard` (which has an empty `hooks.json` of its own).

## Runtime Tools

- **claude binary**: the underlying Claude Code CLI Anthropic ships.
- **claude-wrapper.sh** (also **claudew**): a shell wrapper at `plugins/denubis-plan-and-execute/scripts/claude-wrapper.sh` (`31e42d0`) that the user invokes instead of `claude` directly. It applies a `--disallowedTools` list and sets `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`.
- **Statusline**: a string Claude Code displays on every prompt. Generated by `plugins/denubis-plan-and-execute/scripts/workflow_statusline/` (`4359ab2`), a uv-managed Python package with entry point `workflow-statusline`.
- **uv**: Astral's Python package and project manager. Plugins that ship Python packages (`workflow_statusline`) or scripts (the hook plugins' `.py` files, `denubis-academic`'s bibliography helpers) invoke them via `uv run --project <path>` or `uv run python <path>`.
- **Liveness file** (reader implemented in Phase 3; writer in Phase 8): a key=value text file at `~/.claude/run/<wrapper-pid>.live` that the patched `claude-wrapper.sh` (Phase 8) writes on start and removes on clean exit. A surviving file after the wrapper process disappears signals that the session ended uncleanly. Required keys: `cwd`, `started`, `argv`, `boot_id`. Optional keys (added Phase 2): `start_time` (the wrapper's `/proc` start time, enabling start-time-checked liveness that rejects recycled PIDs) and `session_id` (the live transcript's UUID — bootstrapped by the wrapper at launch and then rewritten to `basename(transcript_path)` on every `SessionStart` by the `update-live-marker.py` hook, so it names the *live* transcript across `/clear` rotation rather than the abandoned launch one; ADR 0003). Extra keys are tolerated for forward compatibility. Parsed by `read_liveness()` and enumerated by `list_liveness_files()` (`plugins/denubis-crash-recovery/scripts/crash_recovery/src/crash_recovery/liveness.py::read_liveness`).
- **Liveness**: frozen dataclass returned by `read_liveness()` carrying `(path, pid, cwd, started, argv, boot_id)`. `pid` is parsed from the filename stem; `boot_id` is defensively lowercased on read (`plugins/denubis-crash-recovery/scripts/crash_recovery/src/crash_recovery/liveness.py::Liveness`).
- **boot_id** (implemented in Phase 3): the kernel-assigned identifier read from `/proc/sys/kernel/random/boot_id`; regenerates on every system boot. Written into the liveness file so that `crash-recovery scan` can recognise liveness files orphaned by a reboot regardless of whether their recorded PID is currently alive. Read by `current_boot_id()` and stored on `Liveness.boot_id`; Phase 4's scan compares the two to set `LivenessState.boot_id_current` (`plugins/denubis-crash-recovery/scripts/crash_recovery/src/crash_recovery/liveness.py::current_boot_id`).
- **pid_alive**: a `bool`-returning predicate over `os.kill(pid, 0)` semantics. Returns `True` for "process exists and is signalable by this user", `False` for both `ProcessLookupError` (no such process) and any `OSError` subclass including `PermissionError` (PID has been recycled to a process this user does not own, so the wrapper itself is gone). The contract is **load-bearing on Phase 2's `classify()` boundary check**: `pid_alive=None` paired with `liveness_state.present=True` raises `ValueError` and crashes the scan, so `pid_alive` must always return a real `bool`. Recorded after Phase 2 proleptic CA2 (`plugins/denubis-crash-recovery/scripts/crash_recovery/src/crash_recovery/liveness.py::pid_alive`).
- **CorrelationKind / CorrelationResult**: StrEnum and frozen dataclass produced by `correlate()`. Kinds: `DIRECT_MATCH` (an exact `<uuid>.jsonl` match — from the marker's `session_id` or an argv `--resume <uuid>`), `MTIME_MATCH` (a single surviving JSONL in the cwd's project dir — first entry inside the tight window `[started-60, started+120]`, and when more than one survives the window, narrowed to exactly one by tmux-resurrect pane corroboration on the candidate's own cwd; Phase 3), `AMBIGUOUS` (more than one in-window candidate that corroboration could not narrow to one — the **full** candidate set is reported, never a filtered subset), `NO_MATCH` (no candidate or no resolvable project dir). Precedence, highest-confidence first: the marker's `session_id` exact match (`correlate.py` "branch 0", ahead of the argv branch — guarded by `test_correlate_session_id_beats_resume_uuid`) → argv `--resume <uuid>` → tight first-entry-ts window scan (with optional tmux-resurrect corroboration; Phase 3) when neither exact match resolves on disk. The `session_id` branch is the highest-confidence path because the `update-live-marker.py` SessionStart hook keeps that field pointed at the live transcript (ADR 0003); a stale launch-time stamp would otherwise mis-resolve after `/clear`. The project directory is resolved by reading the canonical `cwd` from each project's first JSONL entry — NOT by reverse-engineering Claude Code's lossy directory encoding (`plugins/denubis-crash-recovery/scripts/crash_recovery/src/crash_recovery/correlate.py::correlate`).
- **classifier_version** (implemented in Phase 4): an integer constant `CLASSIFIER_VERSION` exported from `crash_recovery.classify`, stamped onto every `sessions` row, every `classification_history` row, and every `scan_runs` row. Phase 4's orphan sweep re-classifies every orphan row regardless of stored version (see **DR10** in the design plan); the upsert path stamps the current value on every touched row. After scan completes, no row carries a stale `classifier_version` (`plugins/denubis-crash-recovery/scripts/crash_recovery/src/crash_recovery/scan.py::_orphan_sweep`, `_upsert_session`).
- **TailKind**: enumerated shape of a JSONL session tail. Eight values: `CONCLUDED`, `TOOL_USE_NO_RESULT`, `ASK_QUESTION_NO_REPLY`, `AGENT_DISPATCH_NO_RESULT`, `EMPTY`, `MALFORMED_TAIL`, `MISSING_FILE`, `UNKNOWN`. Produced by `parse_tail`; consumed by the classifier rule table (`plugins/denubis-crash-recovery/scripts/crash_recovery/src/crash_recovery/jsonl.py::TailKind`).
- **TailSummary**: frozen dataclass returned by `parse_tail` carrying `(kind, last_ts, total_entries, state_summary)`. `state_summary` is the one-line human-readable description persisted as `sessions.state_summary` (`plugins/denubis-crash-recovery/scripts/crash_recovery/src/crash_recovery/jsonl.py::TailSummary`).
- **LivenessState**: frozen dataclass passed to `classify()` carrying just what the classifier needs about the liveness file: `(present, boot_id_current)`. Constructed by Phase 4's scan from a Phase 3 `Liveness` record. `present=True` paired with `pid_alive=None` is a caller-contract violation — `classify()` raises `ValueError` (`plugins/denubis-crash-recovery/scripts/crash_recovery/src/crash_recovery/classify.py::LivenessState`).
- **ClassificationValue**: a `StrEnum` derived at module load from `db.CLASSIFICATION_VALUES` via the functional `StrEnum(name, mapping)` form. Members `LIVE`, `HARD_CRASH`, `BORDERLINE`, `CONCLUDED`, `IRRECOVERABLE` map to the matching CHECK-constraint strings. Single authoritative source per the project's "Schema Constants from Authoritative Source" convention (`plugins/denubis-crash-recovery/scripts/crash_recovery/src/crash_recovery/classify.py::ClassificationValue`, `CLAUDE.md`).
- **parse_tail / classify**: the two pure functions forming crash-recovery's Functional Core. `parse_tail(path, n=20)` reads the last `n` lines with a memory-bounded `deque(maxlen=n)`, keeps only `assistant` / `user` entries (deny-list filter; everything else is bookkeeping), and returns a `TailSummary`. `classify(tail_summary, liveness_state, pid_alive)` walks an immutable `RULES` tuple with first-match semantics and returns a `Classification` carrying a non-empty `reason` slug (`docs/implementation-plans/2026-05-08-crash-recovery/phase_02.md`).
- **ScanContext** (Phase 4): frozen dataclass passed to `run_scan`. Carries `(db_path, run_dir, projects_root, now)`. `now` is a unix epoch injected for test determinism (`plugins/denubis-crash-recovery/scripts/crash_recovery/src/crash_recovery/scan.py::ScanContext`).
- **ScanRunResult** (Phase 4): frozen dataclass returned by `run_scan`. Carries `(scan_run_id, sessions_scanned, sessions_reclassified)` — the `scan_runs` rowid plus filesystem and orphan-sweep counts (`plugins/denubis-crash-recovery/scripts/crash_recovery/src/crash_recovery/scan.py::ScanRunResult`).
- **SessionFact** (Phase 4): read-only frozen dataclass produced by `_walk_sessions` per session UUID found. Carries `(uuid, project_path, cwd, jsonl_path, jsonl_mtime, tail_summary, liveness, pid_alive_value, boot_id_current, ambiguity_candidates)`. The walker computes all liveness-derived fields explicitly at construction time so the boundary-contract invariant `LivenessState.present=True ⇒ pid_alive_value is bool` holds at the `_classify_fact` boundary (`plugins/denubis-crash-recovery/scripts/crash_recovery/src/crash_recovery/scan.py::SessionFact`).
- **orphan sweep** (Phase 4): the second-pass scan operation in `_orphan_sweep`. After the filesystem walk + per-fact upserts complete, it queries `sessions` for every UUID not seen in the current walk, re-classifies each (typically `IRRECOVERABLE/missing_jsonl_on_disk` when the JSONL has vanished, otherwise re-parses the tail and re-runs `classify()` with a synthetic `LivenessState(present=False)`), and UPDATEs the row inside the same transaction. Per **DR10**, the sweep covers all orphans (not only version-stale ones). The Phase 6 annotation exemption (`user_notes IS NOT NULL` → skip entirely) preserves both classification and `classifier_version` so a transiently absent JSONL cannot silently contradict the user's annotation (`scan_db.py::_orphan_sweep` lines 195-205; Task 0).
- **ambiguous_match** (Phase 4): a classification reason produced by `_classify_fact` when `correlate()` returned `AMBIGUOUS` (multiple candidate UUIDs within the mtime window for a single liveness file). The fact is classified as `BORDERLINE/ambiguous_match` without consulting Phase 2's RULES; the `state_summary` is constructed at walk time as `f"{AMBIGUOUS_STATE_SUMMARY_PREFIX}{candidate_uuids_comma_separated}"` and surfaced to the user verbatim. Pinned by `tests/test_scan.py::test_ambiguous_state_summary_uses_pinned_format` (`plugins/denubis-crash-recovery/scripts/crash_recovery/src/crash_recovery/scan.py::_classify_fact`, `AMBIGUOUS_STATE_SUMMARY_PREFIX`).
- **missing_cwd** (Phase 4): a classification reason produced by `_classify_fact` when a JSONL-only session's `_first_entry_cwd` returns `""` (corrupted/truncated JSONL, missing-`cwd`-key first entry). The fact is classified as `IRRECOVERABLE/missing_cwd`; the row is still written so the user can see the corruption in triage, but Phase 7 will not offer a `claudew --resume` for an empty cwd. Pinned by `tests/test_scan.py::test_walk_emits_irrecoverable_missing_cwd_for_unreadable_jsonl` (`plugins/denubis-crash-recovery/scripts/crash_recovery/src/crash_recovery/scan.py::_classify_fact`).
- **SectionKey** (Phase 5): a `StrEnum` with six members: `CURRENTLY_UNFINISHED`, `PROBABLE_CRASH_VICTIMS`, `AMBIGUOUS_CORRELATION`, `NEEDS_INVESTIGATION`, `RECENTLY_CONCLUDED`, `IRRECOVERABLE`. The rendered document order is defined by the `SECTIONS` tuple — which places `PROBABLE_CRASH_VICTIMS` first — not by this declaration order (`plugins/denubis-crash-recovery/scripts/crash_recovery/src/crash_recovery/render.py::SectionKey`).
- **Section** (Phase 5): a frozen dataclass carrying `(key: SectionKey, header: str, empty_message: str)`. Each instance in `SECTIONS` maps a `SectionKey` to its rendered heading and the prose displayed when the section has no rows (`plugins/denubis-crash-recovery/scripts/crash_recovery/src/crash_recovery/render.py::Section`).
- **SECTIONS** (Phase 5): the ordered tuple of six `Section` instances defining document order. `render()` iterates this tuple to emit sections in a stable, reader-expected sequence (`plugins/denubis-crash-recovery/scripts/crash_recovery/src/crash_recovery/render.py::SECTIONS`).
- **LIVENESS_REASONS / NO_LIVENESS_REASONS / JSONL_ONLY_REASONS** (Phase 5): three disjoint `frozenset[str]` constants that partition every reason emitted by `classify.RULES` plus `ambiguous_match` and `unmatched`. `LIVENESS_REASONS` holds reasons that arise only when a liveness file was present; `NO_LIVENESS_REASONS` holds reasons arising only when no liveness file was present; `JSONL_ONLY_REASONS` holds the remaining JSONL-only classification outcomes. Together they drive section assignment (`_section_for_row`) and reduced-confidence rendering (`_reduced_confidence_text`). The partition-exhaustiveness invariant is locked by `tests/test_render.py::test_reason_prefix_partition_is_exhaustive` (`plugins/denubis-crash-recovery/scripts/crash_recovery/src/crash_recovery/render.py::LIVENESS_REASONS`, `NO_LIVENESS_REASONS`, `JSONL_ONLY_REASONS`).
- **render** (Phase 5): the top-level entry point for markdown generation. `render(db_path: Path) -> str` opens the DB read-only (`file:...?mode=ro` URI), queries all `sessions` rows sorted `last_scanned DESC, uuid ASC`, groups them into six sections via `_section_for_row`, and returns a single markdown string terminated by exactly one `\n`. The same DB state always produces byte-identical output (locked by `tests/test_render.py::test_render_is_byte_identical_across_calls` and the three snapshot tests). (`plugins/denubis-crash-recovery/scripts/crash_recovery/src/crash_recovery/render.py::render`).
- **Strikethrough resume marker** (Phase 5): for rows with `classification == "irrecoverable"` (covering both `missing_jsonl_on_disk` and `missing_cwd`), the entry opener is `~~no resume — <reason>~~` (with em-dash U+2014) instead of the `claudew --resume <uuid>` command line. The reduced-confidence line is also suppressed. This marker encodes the Phase 4 coherence-review falsification anchor (commit `b79dd05`): irrecoverable rows must not advertise a resume command. Pinned by `tests/test_render.py::test_irrecoverable_row_suppresses_resume_command` (`plugins/denubis-crash-recovery/scripts/crash_recovery/src/crash_recovery/render.py::_render_entry`).
- **note module** (Phase 6): `crash_recovery.note` exposes `set_note(db_path, uuid, text)` and `clear_note(db_path, uuid)`; both raise `UnknownSessionError` (subclass of `LookupError`) when `rowcount == 0`. The CLI subcommand maps the error to exit code 2 with stderr message.
- **history module** (Phase 6): `crash_recovery.history` exposes `HistoryEntry` frozen dataclass and `fetch_history(db_path, uuid) -> tuple[HistoryEntry, ...]`. SELECT joins `classification_history` with `scan_runs`. Empty result → empty tuple at the module boundary; the CLI maps empty to exit code 1 with stderr message (asymmetric with `note`'s exit 2 — deliberate, see test docstring).
- **prune module** (Phase 6): `crash_recovery.prune` exposes `Candidate` and `PruneSurvey` frozen dataclasses and the read-only `survey(db_path)` + write-only `delete_candidates(db_path, uuids)` split. Four-condition guard enforced by `survey`; `delete_candidates` takes UUIDs verbatim.
- **list_live module** (Phase 6): `crash_recovery.list_live` exposes `LiveEntry` frozen dataclass and `survey_live(run_dir) -> tuple[LiveEntry, ...]`. Filters dead PIDs; reports `boot_id_current` flag but does NOT filter on it.

## Behaviour Surfaces

- **`additionalContext`**: a string a hook can return inside `hookSpecificOutput`. Claude Code prepends it to the model's context for the current turn. Used heavily by `denubis-hook-skill-reinforcement` (`UserPromptSubmit`), `denubis-basic-agents` and `denubis-plan-and-execute` session-start hooks, and `denubis-hook-claudemd-reminder`.
- **`permissionDecision`**: `"allow"` or `"deny"`, returned by a `PreToolUse` hook to permit or block a tool call. Used by `denubis-hook-gh-fork-guard` and the `code-quality-guard` hook in `denubis-plan-and-execute`.
- **`decision: "block"`**: a `Stop` hook output that prevents the turn from closing, surfacing a `reason` to the user. No shipped plugin currently emits it.
- **MCP server**: an external tool provider connected to Claude Code via the Model Context Protocol. The marketplace consumes MCP (Gmail/Calendar/Drive, `context7`, `ast-grep`) but does not host servers.

## Repository Conventions

- **Version-sync invariant**: when any plugin's `plugin.json` changes version, the same change must appear in `.claude-plugin/marketplace.json` and a `CHANGELOG.md` entry must be added in the same commit (`CLAUDE.md`, `b9bed28`).
- **HALT-when-sideways**: discipline of pausing to discuss when the repo state, a design decision, a tool result, or a reviewer finding looks contradictory — rather than working around the anomaly (`CLAUDE.md`, `b9bed28`).
- **`denubis-` prefix**: every plugin in this repo carries the prefix to distinguish from the upstream `ed3d-plugins` fork from which the repo was renamed.

## Workflow Artefacts (under `docs/`)

- **Design plan**: a markdown file under `docs/design-plans/<date>-<slug>.md` produced by `denubis-plan-and-execute`'s design pipeline. Captures Summary, Definition of Done, Acceptance Criteria, Glossary, Architecture, Data Model, Decision Record, Existing Patterns, Implementation Phases.
- **Implementation plan**: a per-task plan under `docs/implementation-plans/<plan>/`, generated from a design plan's phases by the `impl-plan-write` skill.
- **Test plan**: a manual test plan under `docs/test-plans/`, generated by the `test-analyst` agent after a code-review pass.
- **Architecture docs**: this directory (`docs/architecture/`).
