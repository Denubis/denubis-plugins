## Findings

Per-entry verdicts from the independent Sonnet audit. Each test: PASS = the entry isolates genuine human judgment on that axis; FAIL = the entry collapses to an automatable check on that axis.

### 1. DR-AC4.5 — Self-application walk-through and vulnerability acknowledgement
- **Decomposition:** PASS — automatable half is keyword/structure presence; non-automatable half is genuineness of the probe ("genuinely probes… or rubber-stamps"). No overlap.
- **Reduction:** PASS — a single reading-and-reflection act; sub-questions are facets of one qualitative read, not independent checks.
- **Disagreement:** PASS — "genuinely probes vs rubber-stamps" is an authenticity call two readers could split on.
- **Overall: PASS (retain).**

### 2. DR-P1-DR1 (back-ref) — Self-application file helps evaluate a novel skill-authoring moment
Back-ref form (no explicit automatable/not lines); Decomposition applied to the falsification block alone.
- **Decomposition:** PASS — claim under test ("the walk-through helps them evaluate the new case") is a transfer/felt-experience judgment, not a checkable mechanism.
- **Reduction:** PASS — one continuous use-in-the-wild session, not chained independent checks.
- **Disagreement:** PASS — "ends up having to re-derive from scratch" has real interpretive slack (partial help vs full re-derivation).
- **Overall: PASS (retain).**

### 3. DR-P1-DR2 (back-ref) — Companion citations file load-bearing at decision time
- **Decomposition:** FAIL — falsification keyed on file-access frequency ("reach for it every time" / "never loaded"), an observable fact recoverable from transcripts, not a felt-experience call.
- **Reduction:** FAIL — "every rubric use requires loading both files" / "never loaded" is a frequency count, mechanically aggregable.
- **Disagreement:** FAIL — whether a file was opened converges to one answer for any careful auditor.
- **Overall: FAIL.** Recommendation: re-route the access-frequency signal to test-requirements.md; rewrite the human entry to the genuine judgment — *when the file was consulted, did its content change the decision, or would SKILL.md's paraphrase have sufficed?*
- **Orchestrator verification:** Confirmed sound against the entry text. The "It's wrong if" clause is stated purely as load-both-files / never-loaded frequency.

### 4. DR-P1-DR4 (back-ref) — Verbatim wording beats paraphrase in rubric use
- **Decomposition:** PASS — "cognitively workable" / "mentally re-translate" names an internal mental event not recoverable by grepping phrase usage.
- **Reduction:** PASS — same self-report judgment applied across phases, not a chain of automatable sub-checks.
- **Disagreement:** PASS — "consistently need to mentally re-translate" is a contestable read of behaviour.
- **Overall: PASS (retain).** (A cheaper automatable proxy exists — grep for paraphrase-vs-verbatim usage — but it doesn't capture the construct, so the entry still isolates genuine judgment.)

### 5. DR-P2-DR8 — Rubric-callback placement achieves pre-authoring timing
- **Decomposition:** PASS — line-index position + cross-ref resolution (automatable) vs cognitive timing during authoring (not). Clean split.
- **Reduction:** PASS — single self-report during one continuous authoring act.
- **Disagreement:** PASS — "committing to phrasing choices" has a fuzzy boundary two authors/reviewers could split on.
- **Overall: PASS (retain).**

### 6. DR-P2-DR3 — "Dial back aggressive language" guidance changes authoring behaviour
- **Decomposition:** FAIL — the stated non-automatable judgment is not what the procedure tests. The "To shatter it" is "count CRITICAL:/YOU MUST occurrences, compare to baseline" — a raw text metric that cannot distinguish "guidance failed" from "author consciously overrode with a documented reason."
- **Reduction:** FAIL — "audit N additions, count, compare" is a multi-step grep-and-diff, each step scriptable.
- **Disagreement:** FAIL — a count against a numeric baseline is arithmetic; two auditors would not disagree.
- **Overall: FAIL.** Recommendation: move the count to test-requirements.md (automated grep+diff); rewrite to require reading the context of each flagged occurrence and judging *documented reasoned exception vs unreflective habit*.
- **Orchestrator verification:** Confirmed sound. Notable because this entry already carried the `What's automatable` / `What's NOT automatable` header lines (the AC6.1 template) yet still smuggled an automatable count in its falsification procedure. **Meta-finding: the template header lines are necessary but NOT sufficient — the Task 4 collation audit (structural gate) is what catches this class.** This is live evidence for Phase 6's two-layer design.

### 7. DR-P3-DR7 — Rubric-callback placement fires before testing investment begins
- **Decomposition:** PASS — mirrors DR-P2-DR8: line-position/cross-ref (automatable) vs cognitive timing during testing (not).
- **Reduction:** PASS — one continuous testing-session self-report.
- **Disagreement:** PASS — "what counts as invested" is a fuzzy-boundary judgment.
- **Overall: PASS (retain).**

### 8. AM2-P3 — Fable-tier verification is a human-invoked manual checkpoint
- **Decomposition:** PASS — RED/GREEN on Haiku/Sonnet/Opus + grep for absent auto-dispatch (automatable) vs "whether the skill reads correctly when the executor IS a Fable 5 main loop" (structurally not automatable; the cost gate forbids automating it).
- **Reduction:** PASS — "does checklist density visibly flatten Fable output vs an Opus run" is a single live-session comparative judgment with no objective metric.
- **Disagreement:** PASS — "visibly flatten or degrade" is a subjective prose-quality comparison.
- **Overall: PASS (retain).** Correctly caught despite the non-`DR-` heading.

### 9. DR-P5-FRUST-1 — Frustration-signal audit categorisation
- **Decomposition:** PASS — query execution / UUID unioning / context collection (automatable) vs per-match category assignment ("a regex pass cannot make these distinctions reliably"). Cleanest split of the nine.
- **Reduction:** PASS — a single categorisation act repeated per match, with designed-in calibration scaffolding (blinded recategorisation, fatigue floor).
- **Disagreement:** PASS — explicit, designed-in disagreement space (under-report vs over-report), with a blinded-recheck mechanism that only makes sense if disagreement is expected.
- **Overall: PASS (retain).**
