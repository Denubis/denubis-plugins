**Goal:** Create a project context inventory system that helps Claude Code subagents discover project-specific conventions

**Architecture:** Python discovery script scans project for CLAUDE.md files, MCP configs, and installed plugins, then outputs structured markdown. Command invokes script, wrapper skill filters and injects context into subagent prompts.

**Tech Stack:** Python 3.13+, shell scripts, Claude Code skills/commands

**Scope:** 6 phases from original design (phases 1-6)

# Inject Project Context

Read the project context inventory and return a formatted block for inclusion in subagent prompts.

## Overview

This is a utility skill called by other skills before spawning subagents. It reads `.ed3d/project-inventory.md` (generated by `/inventory-project`), applies the requested filter, and returns a formatted context block.

**This skill is not user-invocable.** It's called programmatically by other skills.

## Filter Options

When invoking this skill, specify one of these filters:

| Filter | Includes | Use Case |
|--------|----------|----------|
| `full` | All sections | Implementation agents, code reviewers |
| `commands-only` | Command patterns only | Brainstorming, quick context |
| `tools-only` | MCP servers and plugins only | Tool-aware agents |

## How to Use This Skill

Other skills should invoke this skill before constructing subagent prompts:

1. Check if `.ed3d/project-inventory.md` exists
2. If exists, read and filter based on the skill's needs
3. Include the filtered content in the subagent prompt under a `PROJECT_CONTEXT:` section

### Example Invocation Pattern

In your skill, add this before spawning a subagent:

```markdown
## Project Context Injection

Before constructing the subagent prompt, check for project context:

1. Check if `.ed3d/project-inventory.md` exists in the project root
2. If it exists, read the file and apply the appropriate filter:
   - For implementation agents: use `full` filter (all sections)
   - For brainstorming: use `commands-only` filter
   - For code review: use `full` filter
3. Include the filtered content in the subagent prompt as:

```
PROJECT_CONTEXT:
[filtered inventory content here]
```

If the inventory file does not exist, proceed without project context. Do not error.
```

## Filter Implementation

### Full Filter

Include all sections from the inventory file as-is.

### Commands-Only Filter

Extract only the "Command Patterns" section:

```markdown
## Command Patterns

Commands extracted from project documentation:

- `uv run pytest`
- `ruff check .`
...
```

### Tools-Only Filter

Extract the "MCP Servers" and "Installed Plugins" sections:

```markdown
## MCP Servers

Model Context Protocol servers configured for this project:

- ast-grep
...

## Installed Plugins

Claude Code plugins available in this environment:

- **denubis-plan-and-execute** v2.1.0 (user)
...
```

## Graceful Degradation

**If `.ed3d/project-inventory.md` does not exist:**

Do not error. Return an empty PROJECT_CONTEXT block or omit it entirely.

Skills using this pattern should document this behavior:

```markdown
If no project inventory exists, the subagent will proceed without project-specific context.
This is expected for projects that haven't run `/inventory-project`.
```

**If the inventory file exists but a requested section is missing:**

Return what exists. If the "Command Patterns" section is empty, the commands-only filter returns:

```markdown
## Command Patterns

Commands extracted from project documentation:

*None found*
```

## Implementation Notes

**Design clarification:** The original design described this as a "wrapper skill" that would be "called" by other skills. After codebase investigation, we found that skills in this plugin follow a pattern-based approach - they document conventions that the executing agent follows, rather than providing callable functions.

This skill defines a **documented pattern**, consistent with how other utility patterns work in this plugin (e.g., how `.ed3d/implementation-plan-guidance.md` is used). Skills that use project context injection should:

1. Read the inventory file directly (it's just markdown)
2. Parse and filter using simple text processing (section headers are `## Section Name`)
3. Include the result in subagent prompts

**Why pattern-based:** Claude Code skills cannot return values to callers. They execute in-context and guide agent behavior. The design's intent (consistent context injection with defined filters) is achieved through documented patterns that skills follow.

This approach:
- Matches existing patterns in the codebase
- Avoids duplication by centralizing filter definitions
- Ensures consistency across skills that use project context
