# Proposal 2: Identity

Proposer: Claude Opus 5.5, xhigh (named by Brian, 2026-10-09). Probes were read-only and run
2026-10-09 on Claude Code 2.1.290–2.1.295, codex-cli 0.160.1 with app-server daemon 0.162.0,
agy 1.3.1. Labels: **O** observed, **I** inferred, **A** assumed.

## 1. Challenge

Every session needs one address it can state and that mail can be sent to, unchanged by
clear, compact and resume, new on a fresh launch, distinct for two sessions in one
worktree, and unaffected by rename. The assumption protected: **a message addressed today
reaches the same working context tomorrow, and never a different one.** No vendor
identifier gives this (table below), so the address must be ours, and vendor identifiers
are only evidence bound to it.

| Event | Claude `session_id` | Claude PID, socket | Codex thread id |
|---|---|---|---|
| `/clear` | **changes** (O: `SessionStart:clear` heads a new transcript, 2.1.29x) | same (O: registry pid 43844 kept name and socket, took the new id) | **changes** (O: ADR 0007 `e2e.log`, 0.157.0) |
| compact | same (O: 6 mid-file `SessionStart:compact` records, 2.1.29x) | same | same (O: 6 `compacted` records inside one rollout) |
| resume | same (O: 170 records, 2.1.158–2.1.283; none on 2.1.29x) | **changes** (O: socket is `cc-socks/<pid>.sock`) | same (O: a thread of 19 Sept, one file, one `session_meta`, still written 8 Oct, across a reboot) |
| fork | new (I: one `SessionStart:fork` record heads its own transcript) | not checked | new (A) |

## 2. Mechanism

**Address.** `ag-` plus ten random base32 characters, immutable, generated by us, derived
from nothing. Aliases are mutable names over it.

**Four tables in the Record's Postgres store:**

```sql
create table agent (
  address     text primary key check (address ~ '^ag-[a-z2-7]{10}$'),
  vendor      text not null,             -- claude | codex | agy
  kind        text not null,             -- main | teammate
  parent      text references agent,     -- causation only, never authority
  forked_from text references agent,
  acked_at    timestamptz,               -- first model-run whoami
  created_at  timestamptz not null default now());
create table agent_alias (
  alias text not null check (alias ~ '^[a-z0-9][a-z0-9._-]{0,62}$'),
  address text not null references agent,
  source text not null,                  -- brian | task | vendor | generated
  since timestamptz not null default now(), until timestamptz);
create unique index agent_alias_live on agent_alias (alias) where until is null;
create table agent_session (             -- permanent: vendor session -> address
  vendor_session text primary key, address text not null references agent,
  source text not null, first_seen timestamptz not null default now());
create table agent_presence (            -- rebuildable: where the address is now
  address text primary key references agent, vendor_session text not null,
  boot_id text, pid int, proc_start bigint,      -- the interactive vendor process
  tmux_pane text, pane_evidence text,            -- env | vendor-file | proc-lock | status-panel | spawn
  seen_at timestamptz not null default now(),
  unique (boot_id, pid, proc_start));
```

**Enrolment** is one idempotent call, `agent-id enrol` (command name is a placeholder),
made by a hook where one is reliable and otherwise by the session's first mail command.
The caller is always resolved from its environment; there is no `--as`.

- Claude: `SessionStart` hook on every source. Payload `session_id`, `source`; env
  `CLAUDE_PID`, `TMUX_PANE`, `CLAUDE_CODE_SESSION_ID` (O: all three present in a real
  PreToolUse hook process of my own session, 2.1.295; payload id equals the env id, O via
  the approver's per-session state file).
- Codex: whichever comes first of any hook payload or a tool call reading `CODEX_THREAD_ID`
  (O: equals the thread's own `id`, including in a sub-agent, 0.153–0.156). No dependence on
  `SessionStart` timing (ADR 0007).
- agy: `PreInvocation` hook payload `conversationId` (documented in the bundled `hooks.md`,
  not observed live; O on disk: `conversations/<id>.db`, `presence/<id>.lock`, and
  `history.jsonl` rows carrying `conversationId`).

**Resolution, in one transaction:**

1. `vendor_session` already in `agent_session` → that address. Covers compact, resume,
   repeat hooks, and stale ids held by long-lived children.
2. Fork marker → new address with `forked_from`.
3. Session is new *and* the caller's interactive vendor process `(boot_id, pid,
   proc_start)` owns a presence row → same address. This is `/clear`. Claude applies it only
   when `source = clear`; Codex only when the thread id (UUIDv7, O) was minted after that
   row's `seen_at`.
4. Env `AGENT_EXPECT=<token>` matches a pre-allocated address → bind (spawn).
5. Otherwise a new address and a generated alias.

**Alias.** Stem by the August preference order (Brian rename, task or role, vendor name,
repository or worktree), plus a `coolname` word; uniqueness is the index, with retry.
`agent-id rename` closes the old row and opens a new one; a closed alias still resolves to
its address until someone else takes it. `exec-session-naming` names the tmux *window*,
which holds several panes (O: one window, eight panes), so it supplies a stem only.

**How a supervisor learns a target's address** (`agent-id who --pane %N`), strongest first,
never cwd, title or timing:

1. It spawned the pane: `agent-id expect` pre-allocates the address and passes
   `AGENT_EXPECT` with `tmux split-window -e`.
2. A presence row whose pane came from the session's own environment.
3. A vendor file read from outside: Claude `~/.claude/sessions/<pid>.json` (O: holds
   `sessionId`, `tmux: main:@24.%60`, `name`, `procStart`; undocumented); Codex `/proc`
   session locks in the pane's foreground group (ADR 0007).
4. Codex pane with neither: the existing `/status` read through the guarded actuator when
   Ready. Otherwise `unresolved`, and the verb refuses.

**Sub-agents.** A Claude teammate is a full session (O: I am one; own PID, session id,
socket, pane, own `SessionStart`, and `--parent-session-id` on its command line), so it
gets its own address with `parent` set. In-process Claude sub-agents and Codex native
sub-agents get **no address**: they send as the parent, stamped `via` (Codex child thread
id, O; Claude `agent_id`, A), and replies go to the parent.

**Presenting identity after compact.** Claude: the hook prints one line on every source;
O: `SessionStart:compact` output is rendered to the model as a system reminder. Codex: no
compact hook is established, so identity is pull-recoverable and piggybacked: `agent-id
whoami` takes no arguments, every mail result and Stop nudge starts with the identity
line, and one standing sentence in `AGENTS.md` says the address comes from `whoami`. The
first model-run `whoami` sets `acked_at`.

## 3. Verification

| Claim | Falsifying test |
|---|---|
| `/clear` keeps the address | Live Claude pane: `whoami`, `/clear`, `whoami`. Fails if addresses differ or `agent_session` lacks two ids |
| Compact re-presents it | After `/compact` the transcript's `SessionStart:compact` record contains the address |
| Resume keeps it, launch does not | Quit, `claude --resume`: same address, new pid. Plain `claude` in that pane: new address |
| One worktree, two sessions | Two launches in one cwd give two addresses and two aliases; concurrent alias inserts, one fails |
| Rule 3 cannot merge strangers | Presence row with the same pid, different `proc_start`: no match. `/resume` of a never-enrolled session: new address |
| Codex self-identification | `whoami` in a spawned and a hand-launched pane equals the id in `/status` |
| `who --pane` never guesses | Two Codex sessions in one cwd; a daemon-attached pane returns `unresolved` |
| Rename keeps routing | Mail to the old alias after rename lands on the same address |

## 4. Interfaces

- **Record:** hosts the tables; messages store `address`, never alias or vendor id.
- **Deliver:** gets `where(address)` → vendor, session, pane, evidence, `seen_at`; must
  re-check the process triple before typing. Identity needs its actuator for `/status`.
- **Acknowledge:** attributes an ack by the same environment resolution.
- **Supervise:** `expect` at spawn; `who --pane`; its `--clear` verb writes the new binding
  itself. Roles key on address; identity grants none.
- **Authority:** address, alias and pane confer nothing (AC12.5).
- **Human surface:** alias, vendor, pane, last seen, parent; an address with no live
  presence and unacknowledged mail is listed, not hidden.

## 5. Failure modes

- **Hand-launched Codex is daemon-hosted.** O: panes %45, %9, %13 (`codex`, `codex resume`)
  hold no lock; one `codex app-server` (pid 825369, no tty, no `TMUX_PANE`) holds five locks
  and five rollouts. Only panes launched with explicit `-s … -c model_catalog_json=…` flags
  (%63, %46, %34; I: spawner-launched) hold their own. So (I) such a session cannot name
  its pane, rule 3 is unavailable, and a `/clear` typed by Brian yields a new address. The
  old address goes dormant and its mail surfaces; nothing is lost silently.
- One session resumed in two live processes: presence keeps the newest and the human
  surface shows the conflict; neither is silently fenced.
- Hook absent or untrusted: enrol at first mail command; until then `who --pane` uses
  steps 3–4.
- Postgres down at `SessionStart`: exit 0, print "identity unavailable, run whoami".
- Vendor file or lock layout changes: that step returns `unresolved`.
- Pid reuse or reboot: `boot_id` and `proc_start`. Pane ids are stored with the tmux
  server pid.
- Hook and tool call race: primary key, `on conflict do nothing`, re-read.

## 6. Rejected

- **Vendor session id as address** (Local Mail's `mail-sha256(key)`): rotates on `/clear`.
- **tmux pane as address:** a fresh launch in the pane inherits it; daemon-hosted Codex
  cannot see it.
- **Claude's native name and socket:** Claude only, PID-keyed, and a teammate has no
  registry file (O: mine has a socket and no `<pid>.json`).
- **The August seven-identifier model with digest acknowledgement:** more than the events
  require; one process triple does the fencing.
- **A typed nonce handshake to bind panes:** costs a model turn and types into panes.
