# Token and word estimator design

Status: implemented and fixture-tested. The bundled verifier reproduces the live
corpus using the rules below; an independent methodological audit remains required
before publication.

## Purpose

Report two distinct measures of AI-assisted work:

- model output tokens, split between human-steered root threads and subagents;
- words in human-authored input.

These units are not interchangeable and must not be presented as a ratio. The
estimator reads Claude Code and Codex logs without modifying them.

## Core rule

Count each unit of generated output once, at its origin. Replayed parent context is
not new child work; output generated by a child is new work and remains additive.

Claude and Codex encode those facts differently, so they require different dedupe
mechanisms.

## Claude output tokens

Claude assistant records have a stable `message.id`.

1. Scan main and subagent JSONL files.
2. Group assistant records globally by `message.id`.
3. Use the maximum `output_tokens` recorded for that ID. Repeated records may be
   streaming updates or context replay; summing them double-counts output.
4. Classify the message as main if its ID occurs in any main-thread file; otherwise
   classify it as subagent output.
5. Attribute the retained maximum to the `cwd` on the occurrence that supplied it,
   using lexical `cwd` order as the deterministic tie-break for equal maxima.

For an exact time window, the message origin is the earliest main occurrence when
the ID occurs in main, otherwise the earliest subagent occurrence. The complete
deduplicated message belongs to that origin time. A replay inside the window cannot
pull an older message into it, and a later replay or streaming update cannot push a
message that originated inside the window out of it.

## Codex output tokens

Codex rollout files contain cumulative output counters but no stable per-message ID.
The first `session_meta` identifies the rollout thread and its `source` identifies
root versus subagent.

Modern subagent files may replay the parent's cumulative token events before the
first `Message Type: NEW_TASK` record. The parser therefore derives a child-owned
cumulative series:

1. A root thread uses its recorded cumulative counter unchanged.
2. A legacy subagent with no `NEW_TASK` boundary retains its per-file cumulative
   counter. The live verifier flags a large initial value because that would make
   replay indistinguishable from independent work.
3. A modern subagent with no token events before `NEW_TASK` starts a fresh counter.
4. A modern subagent with replay before `NEW_TASK` uses the maximum replayed value as
   its baseline.
   - If the first post-task value is at least that baseline, the counter continued;
     subtract the baseline from every post-task value.
   - If the first post-task value is below the baseline, the runtime reset the
     counter; use the post-task values unchanged.

The replay baseline is independently compared with the parent's cumulative value at
the fork time. Post-task counters must be monotonic. The verifier reports classifier
mode counts and fails the boundary check on an unresolved replay parent, a replay
mismatch, a post-task regression, or an ambiguous legacy start.

Thread-owned final output is the maximum of the owned cumulative series. Root and
child totals are additive only after replay removal.

## Human input words

### Claude

- Read main-thread user records only.
- Deduplicate by user `uuid`, retaining the earliest timestamp so filesystem
  traversal order cannot move a turn across a time boundary.
- Drop `toolUseResult` and `isMeta` records.
- Count text blocks unless their leading tag is in the named machine-wrapper
  allow-list in `scripts/verify.py`.

The exclusion is deliberately not "starts with `<`". Human prompts can contain
HTML, XML, or pasted agent output.

### Codex

- Read root threads only.
- Read `response_item` messages whose role is `user`.
- Drop only the named machine markers in `scripts/verify.py`, including injected
  environment, skill, subagent-notification, abort, and `AGENTS.md` payloads.
- Do not text-deduplicate. Repeated short human messages are distinct sends.

Pasted content remains human input by the owner's explicit policy.

## Exact windows

`estimate.py --start <ISO> --end <ISO>` applies one timezone-aware,
inclusive/exclusive interval: `[start, end)`. Both arguments are required, `start`
must precede `end`, and exact windows cannot be combined with `--month`.

- Claude output is included by the deduplicated message origin described above.
- Codex output is `max(owned counter before end) - max(owned counter before start)`.
- Human turns are included by their retained timestamp.

This is a structural time slice, not a topical one. Excluding unrelated work requires
a separately documented audit adjustment; project names, dates, and topic exclusions
must never be hard-coded into the estimator.

Boundary precision is limited by the source logs. Claude assigns a whole assistant
message to its origin time. Codex assigns increments between emitted cumulative counter
events. A publication should state those granularities.

## Attribution and rollup

People roots come from `~/.token-estimator`; without that configuration the target
directory is the only root. Longest-prefix matching maps recorded `cwd` strings to
person and project. A project-local `.token-estimator` may map current and historical
paths to one canonical project.

Worktrees remain part of their project. Unrooted paths and person-root activity are
retained rather than silently dropped. Every retained unit lands in exactly one leaf
before person/project rollup.

## Verification architecture

Three different checks serve different purposes:

1. Fixture tests contain small corpora with known answers. They exercise dedupe,
   classification, counter boundaries, window edges, attribution, and word filtering.
2. `scripts/verify.py` checks the live corpus and emits positive boundary diagnostics.
   It verifies the implementation of this method; it cannot establish that the method
   itself is correct.
3. `docs/AUDIT-BRIEF.md` gives an independent actor instructions for attacking the raw
   logs. The actor must not receive `docs/AUDIT-ORACLE.md`; an evaluator compares the
   actor's evidence with that separate oracle.

A check that merely finds no matches is not sufficient evidence. The live verifier
reports the population it examined, classifier modes, and concrete mismatch counts so
an empty defect list is bounded by a positive inventory.

## Known limits

- Log totals grow while sessions are active, so absolute lifetime counts drift.
- Claude message-origin classification assumes replay flows parent to child under the
  same ID; the external audit must continue trying to falsify that assumption.
- Legacy Codex children lack an explicit task boundary. Their counters are accepted
  only while the verifier's ambiguity diagnostic remains clear.
- True Codex resume semantics remain unobserved; repeated own IDs would require an
  explicit continuation rule before they could be counted safely.
- The structural estimator does not decide which project activity is topically in
  scope for a particular disclosure.
