# Using the Token Estimator

## Overview

Report AI effort as **two real measures, never proxies**: machine **output tokens** and
human-authored **input words**. Output is split so the proportion that is autonomous
subagent fan-out vs human-steered main-thread work is visible. The numbers are built to
feed an AI-use disclosure in a registered report, where a wrong split is a publishable
error.

**Core principle — count each unit of work once, at its point of origin.** A replayed
copy in a child context is not new work; a child's own work is new and must not be erased.

## When to use

- "How many tokens / words did this project cost?" — for a methods or disclosure section.
- "What share was subagents vs me?" — main vs sub output split.
- "These directories moved / some belong together" — the `.token-estimator` mapper.
- "Can someone check these numbers?" — the reproducible audit harness.

**When NOT to use:** real-time cost tracking (use `ccusage`); anything needing the *content*
of sessions (this only counts).

## Running it

```
/estimate                     # the project of the current directory, one total
/estimate --dir <path> --month   # one project, rolled up, per-month rows
/estimate --person <name>     # every project under a person
/estimate --all               # every person/project
/estimate --dir <path> --csv out.csv   # also dump tidy leaf grain
```

Scripts (read-only over `~/.claude/projects` and `~/.codex/sessions`):
- `scripts/estimate.py` — the report engine.
- `scripts/verify.py` — single source of truth for the methodology **and** the audit
  harness; re-derives every headline number from the live logs.
- `scripts/mapper.py` — reads `.token-estimator` mappers.

## The two measures

| measure | unit | rule |
|---|---|---|
| output tokens (main) | tokens | assistant output generated in the main thread |
| output tokens (sub) | tokens | assistant output generated by spawned subagents |
| input words | words | human-authored user turns, machine wrappers stripped |

Tokens and words are **different units on purpose** — report them as "N words of human
direction produced M tokens of model output", never as a ratio.

## Methodology in one screen (full detail in `docs/DESIGN.md`)

| node | source | rule |
|---|---|---|
| 1 | Claude tokens | dedup globally by `message.id` (MAX output); classify **main** if the id appears in any main-thread file, else **sub**. Subagent transcripts *replay* the parent's messages — location-based counting double-counts. |
| 2 | Codex tokens | one rollout file = one thread; MAX cumulative `output_tokens`; classify by first `session_meta.source`. Subagents have **independent additive** counters — never merge them into the parent. |
| 3 | Claude words | main-thread files only; drop `toolUseResult`/`isMeta`; drop text blocks whose leading tag is in a **named machine allow-list** (NOT "starts with `<`" — humans paste markup). |
| 4 | Codex words | root threads only; `response_item` `role:user`; drop named machine markers (`turn_aborted`, `skill`, `subagent_notification`, `environment_context`, `# AGENTS.md`). No dedup — repeated `yes`/`continue` are real turns. |
| 5 | attribution | person = root's L1 dir, project = L2; cwd bound to the kept (MAX-token) occurrence so it rides *through* dedup. Reconciles exactly at person grain. |

## Configuration and the mapper

`.token-estimator` is a TOML file with two roles by location:

**`~/.token-estimator` (home) — global config.** Declares the people-roots:
```toml
roots = ["/home/you/people", "/mnt/store/people"]
```
Without it, the tool scopes to the local directory only.

**`<project-dir>/.token-estimator` — a project mapper.** Binds directories (current AND
moved) to one canonical project, so a dir shuffle doesn't fragment its history:
```toml
person  = "Jodie"
project = "BJET-Phase1"
paths = [
  "/home/you/people/Jodie/BJET-current",   # holds this file
  "/home/you/people/Jodie/old-moved-dir",  # history-only; still matches the logs
]
```
Matching is pure longest-prefix on the **recorded cwd string** — moved/defunct paths still
resolve, because the logs already recorded them. After each move, **append** the new path;
never remove old ones.

## Auditing the numbers

The methodology was wrong twice before it was right (a Codex split inverted by mis-merging
subagents; a word count whose method didn't reproduce). Both were caught by reproducibility,
so treat no number as final until it re-derives.

- `python3 scripts/verify.py` — recomputes every headline figure; PASS/FAIL on structural
  invariants (no resumes, subagents additive, person-grain reconciliation), `[base]` on
  point-in-time counts that drift as logs grow.
- `docs/AUDIT-BRIEF.md` + `docs/findings.schema.json` — hand to a *different* engine
  (codex/gemini, read-only) to falsify the methodology independently. Re-running `verify.py`
  only re-checks our arithmetic; the brief attacks the assumptions.

## Common mistakes

| mistake | reality |
|---|---|
| count by file location | subagent transcripts replay the parent → double-counts main |
| sum Codex rollout files | resumes replay the counter (MAX per thread); but subagents are additive (sum *those*) |
| drop any user text starting with `<` or `#` | humans paste markup and write `#` headings — exclude a **named** set only |
| dedup repeated user turns | with no resumes, `yes` ×16 is sixteen real turns |
| report tokens ≈ words | different units; never a ratio |
| trust a number you can't re-derive | if `verify.py` can't reproduce it, it isn't pinned |
